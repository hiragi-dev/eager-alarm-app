# やりたいこと（未実装の改善案）

実装前の要望・検討メモです。着手時点で設計を詰め直す前提の粗いスケッチを含みます。

## 停止方法の一覧で停止位置を地図で確認できるようにする

### やりたいこと

「停止」タブ →「停止方法」の一覧画面で、登録済みの停止方法が **地図上のどこなのか**を
確認できるようにしたい。

### 現状

一覧（`src/components/StopMethodSettings.tsx`）は各項目をピンのアイコン・名前・
「到達判定 半径◯m」というテキストだけで表示しています。緯度経度は保持しているのに
画面には一切出ないため、以下が分かりません。

- 「駅前」「コンビニ」など似た名前を複数登録したとき、どれがどの場所なのか
- 登録時に地図をタップした地点が、意図した場所からずれていないか
- 到達判定の半径が、その場所の実際の広さに対して適切か

地点を確認する手段が現状ないため、**一度削除して登録し直す**しかないのが実態です。
しかもいずれかのアラームに割り当て済みの停止方法は削除できない仕様なので、
確認のためだけにアラーム側の割り当てを外す、という遠回りが必要になります。

### 使えそうな既存の部品

`src/components/LocationPickerMap.tsx` が既に以下を持っており、ほぼそのまま流用できます。

- OpenStreetMapタイルの表示、選択地点のマーカー、到達判定半径の円の描画
- 現在地の青ドット表示と「現在地へ」ボタン
- 高さ・角丸・半径をpropsで指定可能

不足しているのは **閲覧専用モード** です。現状は地図のクリックで必ず
`onSelect` が発火し（`ClickHandler`）、`onRadiusChange` を渡すと半径スライダーが出ます。
一覧からの確認用には、タップしても地点が動かない読み取り専用の状態が要ります。

### 実装案

案A（軽い・推奨）: 一覧の各行をタップすると、その停止方法を中心にした地図をダイアログで
開く。マーカーと半径の円を描画し、編集はできない読み取り専用にする。
`LocationPickerMap` に `readOnly` 相当のpropsを足し、`ClickHandler` の登録と
スライダー表示を抑止すれば済む。削除ボタンは行の `secondaryAction` にあるため、
行タップと操作が競合しない。

案B: 一覧の各行にサムネイル地図（小さな静的な地図）を並べる。一覧性は上がるが、
Leafletのインスタンスが件数分立つため描画コストが重い。静的タイル画像を使う手もあるが
外部サービス依存が増える。

案C: 一覧の上に地図を1つ置き、登録済みの停止方法すべてをピンとして重ねる。
位置関係を俯瞰でき最も分かりやすい一方、画面の作りは一番大きく変わる。

まず案Aで「確認できない」という不便を解消し、登録数が増えて俯瞰したくなった時点で
案Cを検討するのが妥当だと考えています。

### あわせて検討したいこと

- 確認用の地図から、そのまま地点・半径の**編集**に進めるようにするか。現状は編集機能自体が
  なく、作り直しが必要
- 一覧のテキストにも、住所または現在地からの距離を出すか（逆ジオコーディングは外部API
  依存になるため、距離表示のほうが現実的）
